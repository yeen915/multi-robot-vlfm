# 进度检查

只读，不启动也不停止任何东西。

## 步骤

1. 运行状态脚本（先 `source ~/yeen/vlfm_env.sh`）：
   ```bash
   bash .claude/skills/progress/status.sh
   ```
   它列出：正在运行的实验、`outputs/eval/` 下最近的运行（完成数、重跑数、抽查不一致数）、最新运行日志里的报错、server 端口、GPU、内核里的内存故障记录、Tailscale、git 状态。
2. 正在跑的实验：估计还要多久。用 `main/` 里 JSON 的修改时间算每个 episode 的平均用时，乘以剩下的 episode 数。多机器人方法比单机慢。
3. 有报错时：打开对应的 `outputs/eval/<run>/main/logs/<scene>.attempt*.log` 看原因。区分两类：
   - **内存坏位**：下标或数值大得离谱（比如 `index -564867331589327`）、出现 `Corrupted index`。这是硬件问题，评测脚本会自动重跑。
   - **代码问题**：其他异常。要报告给用户，不要自动修。
4. 读 `docs/multi_robot_design.md` 第 5 节当前阶段的条目（标题"**阶段 N：…**"及其下的"进度"列表），列出已完成和未完成的项。
5. 没有实验在跑、但 server 还开着（端口数 > 0）：提醒用户，并问是否关闭（`~/yeen/stop_vlm.sh`）。

## 汇报格式（中文，简短）

- 第一句给结论，例如"实验正常，跑完 33/50，预计 13:20 完成"。
- 然后是要点：完整性情况（重跑几次、抽查是否一致）、报错及其类型、server/GPU 是否该关。
- 当前阶段：已完成 / 未完成的项，一两行。
- 指标出现时用一句通俗的话解释它的含义（见 CLAUDE.md 的沟通要求）。
